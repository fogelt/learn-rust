Hello, Rust!

Rust is a compiled language with the speed of C and a compiler that refuses to let you shoot yourself in the foot. Start small: one function, one macro, one running program.

⏱ 15 min 🦀 Beginner ✎ 1 exercise ✓ Completed
1

Read

The idea

Rust is a compiled systems language used everywhere from operating systems and browsers to command-line tools and web services. It promises three things at once: performance, memory safety, and fearless concurrency. The cost is a strict compiler — but that compiler is also the best teacher you will have.

You do not need Rust installed to use this course. Every practice editor sends your code to the official Rust Playground and shows the real compiler output. Still, installing Rust locally is worth it: you can keep experimenting offline and build real projects.

Install the toolchain

Rust is installed with rustup, a small tool that manages the compiler and its versions.

terminal
# macOS, Linux, or WSL
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# Windows: download and run rustup-init.exe from https://rustup.rs

Close and reopen your terminal, then check that both tools are available:

terminal
rustc --version
cargo --version

You should see a version number and a host triple. That is it — no IDE, no build system to configure, no runtime to install.

Your first Cargo project

Cargo is Rust's build tool and package manager. It creates projects, compiles them, runs tests, and downloads dependencies. Create a new project and run it:

terminal
cargo new hello_rust
cd hello_rust
cargo run

Cargo generates a tiny project that already prints Hello, world!. The layout is deliberately simple:

project layout
hello_rust/
├── Cargo.toml      # package metadata and dependencies
├── Cargo.lock      # exact dependency versions (generated)
└── src/
    └── main.rs     # the entry point

Cargo.toml is the manifest. src/main.rs is where a binary crate starts. Build artifacts go into target/, which you should never commit to version control.

The smallest real program

main.rs
fn main() {
    // Statements end with a semicolon.
    let greeting = "Hello, world!";
    println!("{greeting}");
}
  • fn main() defines the entry point. When the program starts, this function runs first.
  • Braces { ... } form a block. Blocks can contain statements and produce a value.
  • let creates a binding. Bindings are immutable by default — a rule you will meet properly in the next lesson.
  • // starts a comment that runs to the end of the line. /* ... */ is a block comment, and /// documents the item below it.
  • println!("{greeting}") prints a line. The ! means it is a macro, not a function: it expands into extra formatting code at compile time.

The braces inside the string are a placeholder that refers to a variable in scope. You can also use positional placeholders:

main.rs
fn main() {
    let name = "Ferris";
    let legs = 10;

    println!("{name} has {legs} legs.");
    println!("{} + {} = {}", 2, 3, 2 + 3);
}

Macros are everywhere in Rust. println! adds a newline; print! does not; format! returns a String instead of printing. You will meet many more.

The commands you will actually use

CommandWhat it does
cargo new NAMECreate a new package in a new directory.
cargo runCompile the project and run the binary.
cargo buildCompile without running. Output lands in target/debug/.
cargo build --releaseCompile with optimisations. Output lands in target/release/.
cargo checkType-check quickly without producing a binary — great while editing.
cargo testCompile and run the test suite.
Debug vs release

Debug builds are fast to compile and slow to run; they also keep overflow checks on. Release builds optimise aggressively and switch overflow checks off. Use cargo run while learning and cargo run --release when measuring performance.

Quiz
Check yourself


Four questions. Get three or more right to complete the lesson — you can retry as often as you like.





01Which Cargo command compiles your project and then runs the binary?



Why: cargo build only compiles. cargo run compiles if needed and then executes the binary. cargo check type-checks without code generation, and cargo test runs tests.



02What does the ! in println! mean?



Why: The exclamation mark signals a macro call. Macros expand into code during compilation, which is why println! can check format strings at compile time.



03Where does a Cargo binary package put its entry point by default?



Why: A binary crate starts at src/main.rs. src/lib.rs is the entry point for a library crate, which has no main.



04Which line correctly prints Hello, Ferris!?



Why: Each {} placeholder needs a matching argument. The second option supplies none, the third calls a non-existent function without !, and the fourth is JavaScript, not Rust.
