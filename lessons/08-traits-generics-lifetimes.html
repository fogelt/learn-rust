Traits, Generics & Lifetimes

Generics let one function work for many types; traits describe what those types must be able to do. Lifetimes are the third piece: they tell the compiler how long references are valid.

⏱ 26 min 🦀 Beginner ✎ 1 exercise ✓ Completed
1

Read

The idea

Rust has no class inheritance. Instead, behaviour is described by traits, and flexibility comes from generics. This keeps code explicit: a function says exactly which capabilities it needs, and the compiler checks that every concrete type provides them.

Generic functions

main.rs
fn largest<T: PartialOrd>(items: &[T]) -> &T {
    let mut largest = &items[0];

    for item in items {
        if item > largest {
            largest = item;
        }
    }

    largest
}

fn main() {
    let numbers = [3, 9, 2, 7];
    let words = ["pear", "apple", "plum"];

    println!("{}", largest(&numbers));
    println!("{}", largest(&words));
}

The <T: PartialOrd> introduces a type parameter T and a bound: T must implement PartialOrd, because the function uses >. Without the bound, the compiler cannot assume the comparison exists. Generics are compiled into specialised code for each concrete type (monomorphisation), so they cost nothing at runtime.

Structs and enums can be generic too:

main.rs
struct Point<T> {
    x: T,
    y: T,
}

fn main() {
    let integer = Point { x: 3, y: 7 };
    let float = Point { x: 1.5, y: 2.5 };

    println!("{} {}", integer.x, float.y);
}

Traits: shared behaviour

A trait is a contract. It declares methods, optionally with default implementations. Types opt in with impl Trait for Type:

main.rs
trait Describable {
    fn describe(&self) -> String;

    fn shout(&self) -> String {
        self.describe().to_uppercase()
    }
}

struct Book {
    title: String,
    pages: u32,
}

impl Describable for Book {
    fn describe(&self) -> String {
        format!("{} ({} pages)", self.title, self.pages)
    }
}

fn announce(item: &impl Describable) {
    println!("{}", item.shout());
}

fn main() {
    let book = Book {
        title: String::from("Rust in Action"),
        pages: 400,
    };

    announce(&book);
}
  • impl Trait in a parameter position means “any type that implements this trait”.
  • The generic form fn announce<T: Describable>(item: &T) is equivalent but lets you name the type or use it in several places.
  • Default methods like shout can call required methods like describe and can be overridden.
  • A type can implement many traits, and a trait can be implemented for types you did not write (subject to the orphan rule).

Common standard-library traits include Debug, Clone, Copy, PartialEq, PartialOrd, Iterator, and Display. Many can be derived automatically with #[derive(...)]. Traits can also be combined in bounds: T: Describable + Clone.

When you need a collection of different types that share behaviour, use a trait object: Vec<Box<dyn Describable>>. That uses dynamic dispatch instead of monomorphisation — slightly slower, but homogeneous to store.

Lifetimes: how long is a reference valid?

Every reference has a lifetime. Most of the time the compiler infers it, so you never write it down. Sometimes it needs help describing how input and output references relate:

main.rs
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}

fn main() {
    let first = String::from("long");
    let second = "xy";

    println!("{}", longest(&first, second));
}

The annotation does not make anything live longer. It says: the returned reference is valid for at most the shorter of the two input lifetimes, and the caller must respect that. Without it, the compiler rejects the function because it cannot prove the result is safe:

does not compile
// error[E0106]: missing lifetime specifier
fn longest(x: &str, y: &str) -> &str {
    if x.len() > y.len() { x } else { y }
}

Structs that hold references need lifetime parameters too:

main.rs
struct Excerpt<'a> {
    part: &'a str,
}

fn main() {
    let novel = String::from("Call me Ishmael. Some years ago...");
    let first_sentence = novel.split('.').next().unwrap();
    let excerpt = Excerpt { part: first_sentence };

    println!("{}", excerpt.part);
}

Most functions never need explicit lifetimes — this is called lifetime elision. When a struct stores a borrow, or when a function has several reference inputs and returns a reference, you may need to spell out the relationship.

Read lifetimes as constraints, not timers

'a is not a countdown. It is a name for “some region of code”. Saying several references share 'a means they must all be valid for the same region — usually the shortest one involved.

01What is a trait for?



Why: A trait is an interface: a set of methods (and optionally associated items) that a type promises to provide. It enables generic code and trait objects without class inheritance.



02What does the bound T: PartialOrd mean?



Why: The bound tells the compiler which operations are legal inside the generic function. PartialOrd provides comparison operators; without it, item > largest would not type-check.



03What does a lifetime annotation such as 'a actually do?



Why: Lifetimes are compile-time constraints. They never change how long a value lives; they let the compiler prove that no reference outlives the data it points to.



04What does fn print(item: &impl Describable) accept?



Why: impl Trait in argument position is sugar for a generic parameter with that bound. Any type implementing the trait is accepted, and the compiler generates the appropriate specialised function.
