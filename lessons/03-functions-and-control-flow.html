Functions & Control Flow

Functions are the building blocks, and in Rust almost everything is an expression — including if and blocks. That one idea makes return values feel natural.

⏱ 18 min 🦀 Beginner ✎ 1 exercise ✓ Completed
1

Read

The idea

Functions are declared with fn, take typed parameters, and optionally declare a return type with ->. Rust does not care about declaration order: a function can call one defined below it.

main.rs
fn main() {
    let result = add(2, 3);
    greet("Ferris");

    println!("2 + 3 = {result}");
    println!("double(4) = {}", double(4));
}

fn add(a: i32, b: i32) -> i32 {
    a + b
}

fn double(n: i32) -> i32 {
    n * 2
}

fn greet(name: &str) {
    println!("Hello, {name}!");
}

Notice that add has no return keyword. The last expression in a function body is its value, as long as it has no semicolon. Add a semicolon and you turn the expression into a statement that produces () — the compiler will complain that the types do not match.

main.rs
fn absolute(n: i32) -> i32 {
    if n < 0 {
        return -n; // early return is still available
    }
    n // tail expression: this is the result
}

Statements, expressions, and blocks

A statement performs an action; an expression produces a value. Blocks are expressions, so you can initialise a binding from one:

main.rs
fn main() {
    let y = {
        let x = 3;
        x * x
    };

    println!("{y}"); // 9
}

The inner x goes out of scope at the closing brace, while the block's final expression becomes the value of y.

if is an expression

main.rs
fn main() {
    let n = 7;

    if n % 2 == 0 {
        println!("even");
    } else {
        println!("odd");
    }

    let label = if n > 5 { "big" } else { "small" };
    println!("{label}");
}
  • The condition must be a bool. Rust will not treat 0, "", or null as false.
  • Braces are mandatory, even for a single statement. No dangling-else surprises.
  • When if is used as an expression, every branch must produce the same type.
No truthiness

Coming from JavaScript or Python, this feels verbose at first. It also means if user_input is a compile error rather than a bug that appears only when the value is empty.

Loops: loop, while, and for

main.rs
fn main() {
    let mut countdown = 3;
    while countdown > 0 {
        println!("{countdown}");
        countdown -= 1;
    }

    for i in 1..=3 {
        println!("i = {i}");
    }

    let names = ["Ada", "Linus", "Ferris"];
    for name in names {
        println!("Hello, {name}");
    }

    let mut n = 0;
    let first_square_over_50 = loop {
        n += 1;
        if n * n > 50 {
            break n * n;
        }
    };
    println!("{first_square_over_50}"); // 64
}
  • loop repeats forever until a break. A break value; makes the loop itself evaluate to that value.
  • while repeats while a condition is true.
  • for walks an iterator: a range, an array, a vector, or anything else that implements IntoIterator. Prefer for when the number of items is known.

Ranges are half-open by default: 0..5 yields 0, 1, 2, 3, 4. Use 0..=5 to include 5. You can label loops when you need to break out of an outer one:

main.rs
'outer: for x in 0..3 {
    for y in 0..3 {
        if x == 1 && y == 1 {
            break 'outer;
        }
    }
}

Rust also has continue to skip to the next iteration, and for loops are usually faster than hand-written index loops because the compiler knows exactly what is being iterated.

Reading compiler errors

When a function returns the wrong type, read the “expected … found …” pair at the end of the error. Nine times out of ten, a stray semicolon is the culprit. Lesson 7 covers Result for errors you can recover from; this lesson is about the shape of code, not failure handling.
