Vec, String & HashMap

Real programs need data that grows. Vectors hold lists, Strings hold text, and hash maps answer “what is the value for this key?” — all three own their contents on the heap.

⏱ 20 min 🦀 Beginner ✎ 1 exercise ✓ Completed
1

Read

The idea

Arrays have a fixed length known at compile time. A Vec<T> is a growable array on the heap: it owns its elements, tracks its length and capacity, and reallocates as needed. This is the list type you will reach for most often.

Vectors

main.rs
fn main() {
    let mut scores = vec![90, 80, 70];

    scores.push(60);
    scores[0] = 95;

    println!("{:?}", scores);          // [95, 80, 70, 60]
    println!("len = {}", scores.len());
    println!("first = {}", scores[0]);

    match scores.get(10) {
        Some(score) => println!("score at 10: {score}"),
        None => println!("no score at index 10"),
    }
}
  • vec![...] builds a vector from a list of values; Vec::new() starts empty and usually needs a type annotation.
  • push appends, pop removes and returns the last element as an Option<T>.
  • scores[0] panics on an invalid index; get(0) returns Option<&T> and is the safe choice for untrusted indexes.
  • for score in &scores iterates by reference; for score in &mut scores iterates mutably; for score in scores consumes the vector and yields owned values.
main.rs
fn main() {
    let mut numbers = vec![3, 1, 4, 1, 5];

    for number in &mut numbers {
        *number += 10; // dereference the mutable borrow
    }

    numbers.sort();
    numbers.dedup();

    println!("{numbers:?}"); // [11, 13, 14, 15]
}

Vectors must contain a single type. If you need mixed types, use an enum with one variant per type — the same trick works for JSON-like data, as you will see with serde later.

Strings: String vs &str

Rust has two string types that are easy to confuse. A &str is a borrowed view into UTF-8 text — a pointer and a length. A String owns a growable, heap-allocated buffer. String literals are &'static str: they live in the binary for the whole program.

main.rs
fn main() {
    let mut greeting = String::from("hello");
    greeting.push_str(", world");
    greeting.push('!');

    println!("{greeting}");
    println!("chars = {}", greeting.chars().count());
    println!("bytes = {}", greeting.len());
}
OperationNotes
String::from(s), s.to_string()Create an owned string from a borrowed one.
format!("{a}{b}")Build a new String from pieces without consuming them.
push_str(&str), push(char)Append to a mutable String.
&s[a..b]Borrow a byte range. Panics if the boundary is inside a UTF-8 character.
s.chars(), s.bytes()Iterate Unicode scalar values or raw bytes.
s.len()Length in bytes, not characters.

Prefer &str in function parameters — it accepts both literals and &String via deref coercion. Return String when the function creates new text.

Indexing a String

You cannot write s[0] to get a character: UTF-8 characters have variable width, so a byte index is not a character index. Use &s[0..1] only for known-safe ASCII, or iterate with s.chars().

HashMap: key → value

main.rs
use std::collections::HashMap;

fn main() {
    let mut scores: HashMap<String, i32> = HashMap::new();

    scores.insert(String::from("blue"), 10);
    scores.insert(String::from("yellow"), 50);

    println!("{:?}", scores.get("blue")); // Some(10)
    println!("{}", scores.get("green").copied().unwrap_or(0)); // 0

    for (team, score) in &scores {
        println!("{team}: {score}");
    }
}

get returns Option<&V>, so a missing key is not an error. insert replaces any existing value. The entry API combines “look up or insert” in one step, which is perfect for counting:

main.rs
use std::collections::HashMap;

fn main() {
    let text = "the cat and the hat";
    let mut counts: HashMap<&str, u32> = HashMap::new();

    for word in text.split_whitespace() {
        *counts.entry(word).or_insert(0) += 1;
    }

    println!("{counts:?}");
}

or_insert(0) returns a mutable reference to the existing value or inserts 0 and returns a reference to that. Dereferencing with * lets you increment it.

Hash maps do not preserve insertion order, and iteration order can change between runs. If you need sorted keys, use BTreeMap; if you need fast set membership, use HashSet. Keys must implement Eq and Hash.

For small lookup tables, a match or an array is often simpler and faster than a hash map. Reach for HashMap when the key set is dynamic.

01What does scores.get(99) return for a Vec<i32>?



Why: get is the checked lookup and returns Option<&T>. The [] operator is the unchecked one and panics on an invalid index.



02Which method appends a &str to an existing String?



Why: push_str appends borrowed text and returns nothing. push appends a single char. The + operator works but consumes the left-hand String; format! is usually clearer.



03What does map.entry(key).or_insert(0) do?



Why: The entry API gives you a slot for a key. or_insert fills it if needed and returns &mut V, which is why counting uses *map.entry(k).or_insert(0) += 1.



04What does String::len() return?



Why: len returns the byte length. chars().count() returns the number of Unicode scalar values, which can be smaller for non-ASCII text.
