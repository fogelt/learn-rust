Structs, Enums & Matching

Structs group related data; enums describe alternatives. Together with match they let you model a problem so precisely that whole categories of bugs become impossible to express.

⏱ 22 min 🦀 Beginner ✎ 1 exercise ✓ Completed
1

Read

The idea

A struct is a named record: several values bundled together. An enum is a choice between variants, and each variant can carry its own data. Both can have methods. match then forces you to handle every case.

Defining and creating structs

main.rs
struct User {
    username: String,
    email: String,
    active: bool,
    sign_in_count: u64,
}

fn main() {
    let user = User {
        username: String::from("ferris"),
        email: String::from("ferris@example.com"),
        active: true,
        sign_in_count: 1,
    };

    println!("{} is active: {}", user.username, user.active);
}

To modify a field, the whole binding must be mutable: let mut user = .... Rust does not allow individual fields to be declared mutable.

When a variable has the same name as a field, field-init shorthand saves noise. The .. update syntax fills the remaining fields from another value:

main.rs
fn build_user(username: String, email: String) -> User {
    User {
        username, // shorthand for username: username
        email,
        active: true,
        sign_in_count: 0,
    }
}

let updated = User {
    email: String::from("new@example.com"),
    ..user
};

Tuple structs are structs without field names. They are handy for wrapping a single value and giving it a distinct type:

main.rs
struct Meters(f64);

fn main() {
    let distance = Meters(42.0);
    println!("{} metres", distance.0);
}

Methods and associated functions

main.rs
struct Rectangle {
    width: f64,
    height: f64,
}

impl Rectangle {
    // Associated function: no self, called as Rectangle::new(...)
    fn new(width: f64, height: f64) -> Self {
        Self { width, height }
    }

    // Method: borrows the instance immutably
    fn area(&self) -> f64 {
        self.width * self.height
    }

    // Method that mutates the instance
    fn scale(&mut self, factor: f64) {
        self.width *= factor;
        self.height *= factor;
    }
}

fn main() {
    let mut rect = Rectangle::new(3.0, 4.0);
    println!("area: {}", rect.area());
    rect.scale(2.0);
    println!("area: {}", rect.area());
}
  • &self borrows the value and cannot mutate it; use it for read-only methods.
  • &mut self borrows mutably; the caller needs a mutable binding.
  • self takes ownership — useful for builder-style transformations, but the caller loses the original value.
  • Self is an alias for the type the impl block belongs to.

You can implement multiple impl blocks for the same type. Common traits are usually derived instead of written by hand:

main.rs
#[derive(Debug, Clone, PartialEq)]
struct Point {
    x: i32,
    y: i32,
}

fn main() {
    let p = Point { x: 3, y: 7 };
    let copy = p.clone();

    println!("{p:?}");       // Point { x: 3, y: 7 }
    println!("{p:#?}");      // pretty-printed, one field per line
    println!("equal: {}", p == copy);
}

Without #[derive(Debug)], {:?} will not compile. Deriving is opt-in: you only get what you ask for.

Enums with data

Unlike C-style enums, Rust variants can carry data. This makes enums ideal for representing messages, states, and shapes:

main.rs
#[derive(Debug)]
enum Shape {
    Circle(f64),
    Rectangle { width: f64, height: f64 },
    Triangle { base: f64, height: f64 },
}

fn area(shape: &Shape) -> f64 {
    match shape {
        Shape::Circle(radius) => 3.14159 * radius * radius,
        Shape::Rectangle { width, height } => width * height,
        Shape::Triangle { base, height } => 0.5 * base * height,
    }
}

fn main() {
    let shapes = [
        Shape::Circle(1.0),
        Shape::Rectangle { width: 2.0, height: 3.0 },
        Shape::Triangle { base: 4.0, height: 2.0 },
    ];

    for shape in &shapes {
        println!("{:?} -> {:.2}", shape, area(shape));
    }
}

match takes a value, compares it against patterns, and binds the data inside each variant. It must be exhaustive: every variant has to be covered, or you need a _ catch-all. The compiler checks this for you.

main.rs
fn describe(n: i32) -> &'static str {
    match n {
        0 => "zero",
        1..=9 => "single digit",
        n if n < 0 => "negative",
        _ => "large",
    }
}

Patterns can match literals, ranges, tuples, structs, and enum variants. Guards (n if n < 0) add a condition. Use | for alternatives: 1 | 2 | 3.

Option: Rust's answer to null

The standard library defines Option<T> as an enum with two variants: Some(T) and None. A value is either present or absent, and the type system makes you handle both cases:

main.rs
fn index_of(haystack: &[&str], needle: &str) -> Option<usize> {
    haystack.iter().position(|item| *item == needle)
}

fn main() {
    let fruits = ["apple", "pear", "plum"];

    match index_of(&fruits, "pear") {
        Some(index) => println!("pear is at {index}"),
        None => println!("not found"),
    }

    if let Some(index) = index_of(&fruits, "plum") {
        println!("plum is at {index}");
    }
}

if let is shorthand for a match with one interesting arm. while let does the same in a loop. There is no null in Rust, so there is no null pointer to accidentally dereference.

Model the states, not the flags

Instead of a struct with is_loading, has_error, and data fields that can contradict each other, use an enum with Loading, Failed(Error), and Ready(Data) variants. Then impossible states cannot be constructed.

01What does a method taking &self allow?



Why: &self is an immutable borrow. To mutate fields, the method needs &mut self and the instance must be a mutable binding. self by value takes ownership.



02What must a match expression do?



Why: Exhaustiveness is enforced at compile time. It is what makes match safe when a new enum variant is added later: every use site fails to compile until it handles the new case.



03Which pair are the variants of Option<T>?



Why: Option models absence with Some and None. Ok and Err belong to Result, which models success and failure (lesson 7).



04What does #[derive(Debug)] enable?



Why: Debug provides the developer-facing formatting used by {:?}. Equality needs PartialEq, cloning needs Clone, and JSON is handled by external crates such as serde.
