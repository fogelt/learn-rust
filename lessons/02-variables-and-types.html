Variables, Types & Mutability

Rust does not let variables change unless you say so. That sounds annoying until you realise how many bugs come from accidental mutation. Here is how bindings, types, and shadowing work.

⏱ 18 min 🦀 Beginner ✎ 1 exercise ✓ Completed
1

Read

The idea

In many languages a variable is a box you can put a new value into whenever you like. In Rust, a binding is a promise: let x = 5; means x will stay 5 until it goes out of scope. If you want to change it, you ask for permission with mut.

Immutable by default

main.rs
fn main() {
    let level = 1;
    println!("Level {level}");

    // level = 2; // error: cannot assign twice to immutable variable
}

If you uncomment that line, the compiler rejects the program. It does not wait until runtime, and it points at both the declaration and the assignment. To allow reassignment, declare the binding as mutable:

main.rs
fn main() {
    let mut level = 1;
    level = 2;
    level += 1;
    println!("Level {level}"); // Level 3
}

Mutability is per binding, not per type. Two bindings of the same type can have different permissions.

Types: inferred, and occasionally written down

Rust is statically typed, but it usually infers the type from how a value is used. When inference is not enough — or when you want to be explicit — add an annotation after a colon:

main.rs
fn main() {
    let guess: u32 = 42;      // explicitly unsigned 32-bit
    let pi = 3.14;            // f64 by default
    let ready = true;         // bool
    let initial = 'R';        // char
    let title = "Rust";       // &str (a borrowed string slice)
}

Overflow behaves differently per profile

In a debug build, an integer overflow panics. In a release build it wraps around silently. If overflow is possible, be explicit: checked_add returns an Option, saturating_add clamps at the boundary, and wrapping_add wraps.

Shadowing: a new binding with the same name

You can declare a new variable with the same name using another let. This is called shadowing. The new binding can even have a different type:

main.rs
fn main() {
    let spaces = "    ";        // &str
    let spaces = spaces.len();  // usize
    println!("{spaces} spaces"); // 4 spaces
}

Unlike mut, shadowing creates a brand-new value. The old binding still exists until the end of its scope, but it is inaccessible by name. This is handy for transforming a value step by step without inventing names like spaces_str and spaces_count.

Tuples and arrays

Tuples group a fixed number of values of different types. Access fields with . and an index, or destructure them:

main.rs
fn main() {
    let point: (i32, i32) = (3, 7);
    let (x, y) = point;

    println!("x={x} y={y} whole={point:?}");
    println!("first field: {}", point.0);
}

Arrays hold a fixed number of values of one type. Their length is part of the type, so [i32; 3] and [i32; 4] are different types:

main.rs
fn main() {
    let scores: [i32; 5] = [90, 80, 70, 60, 50];

    println!("first={} last={}", scores[0], scores[4]);
    println!("length={}", scores.len());

    // scores[5] would panic: index out of bounds
}

Indexing with [] panics if the index is out of range. When the index comes from user input, prefer get, which returns an Option (lesson 7).

If you need a list that grows at runtime, you want a Vec — that is lesson 6.

Constants

main.rs
const MAX_PLAYERS: u32 = 8;

fn main() {
    println!("A match allows {MAX_PLAYERS} players.");
}

Constants are evaluated at compile time, must have an explicit type, and use SCREAMING_SNAKE_CASE by convention. They can live at module level and are inlined wherever they are used.

Warnings are not failures

Unused variables produce warnings, not errors. Prefix a binding with an underscore (_temp) if you need it to exist but will not read it. Run cargo build and read the warnings — they often point at real mistakes.

Four questions. Get three or more right to complete the lesson — you can retry as often as you like.





01What is the default mutability of a binding created with let?



Why: Bindings are immutable unless declared with mut. The compiler rejects reassignment, which rules out a large class of accidental-state bugs.



02Which declaration allows count = count + 1; later in the same scope?



Why: Only let mut creates a mutable binding. A const is always immutable, and let count: mut i32 is not valid syntax — mut comes before the name.



03What does this do? let x = 5; let x = "five";



Why: The second let introduces a new binding. Shadowing is not mutation: the old value still exists until the end of scope, but the name now refers to the new binding, which can have a different type.



04Which literal is a char?



Why: Single quotes create a char (one Unicode scalar value). Double quotes create a string slice (&str), and b"a" is a byte-string literal.
